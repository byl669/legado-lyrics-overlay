# 阅读·歌词版 — 安装与数据迁移指引

> **定制内容**：阅读（Legado）朗读时显示桌面歌词悬浮窗
> **产物**：`Legado-3.26100808-朗读桌面歌词-共存版.apk`

---

## 一、为什么不能直接覆盖安装

Android 有一条**不可绕过的安全规则**：同一个包名，必须用**同一把私钥**签名，才能覆盖安装。校验发生在系统底层（PackageManagerService），改代码、改清单、root 都绕不过去。

| 项目 | 你手机上的原版 | 原方案的定制版 | 结果 |
|---|---|---|---|
| 包名 | `com.legado.app.release` | `com.legado.app.release` | 相同 |
| 签名 SHA1 | `EF:4F:C2:47:…:3C:6F` | `E7:76:2E:08:…:BE:C2` | **不同** |
| versionCode | 37456 | 30000 | 更低 |

官方发布的签名私钥掌握在作者手里（存在 GitHub Secrets），公开仓库里那把 `.github/workflows/legado.jks` 只是 CI 用的测试签名，指纹对不上。所以"原包名覆盖安装"在技术上做不到。

---

## 二、解决方案：共存版

本版本改用**独立包名**，与原版当作两个 App 并存：

| | 原版 | 本定制版 |
|---|---|---|
| 应用名 | 阅读 | **阅读·歌词版** |
| 包名 | `com.legado.app.release` | `com.legado.app.custom` |
| versionCode | 37456 | 38200 |

- 原版及其中所有数据**原封不动**
- 定制版是独立 App，随时可卸载，不影响原版
- 两边配置、书架、进度各自独立

## 四、把数据搬到定制版（关键步骤）

### 推荐做法：用内置的「备份 / 恢复」

> ### ⚠️ 开始前必须知道的两件事
>
> **① 备份路径要改到公共目录**
> Legado 默认把备份存到 App 私有目录（`Android/data/<包名>/files`），**卸载 App 时会被系统一起删掉**。必须改到「下载 / Download」这类公共目录。下面第 1 步会具体说。
>
> **② 如果原版设过「本地密码」，定制版要设一模一样的**
> Legado 的「本地密码」用来加解密备份里的敏感项。两边密码不同的话，**书架、书源、阅读进度、设置照样能完整恢复**，只有极少数加密项（服务器列表、WebDAV 密码）解不开，会留空。
> 如果你的原版从没设过本地密码，这条可以忽略。

#### 第 1 步 — 在原版里导出备份

1. 打开**原版阅读**
2. 进入 **我的 → 备份与恢复**
3. 先看「**备份路径**」这一项，**务必改到手机存储的公共目录**，例如 `Download`（下载）

   > ⚠️ **这一步最重要**：默认备份路径在
   > `Android/data/com.legado.app.release/files`
   > —— 这个目录在**卸载 App 时会被系统一起删掉**。改到 `Download` 才安全。

4. 返回上一级，点「**备份**」，等待完成（会生成一个 zip 压缩包）

#### 第 2 步 — 安装定制版

按第三节说明安装 **阅读·歌词版**。

#### 第 3 步 — 在定制版里恢复

1. 打开**阅读·歌词版**
2. 进入 **我的 → 备份与恢复**
3. 点「**恢复**」，选中刚才生成的备份 zip
4. 等待完成 —— 书架、书源、阅读进度、阅读设置全部回来了

> **本地书文件不在备份里**（比如放在 `Download/Books` 的 txt）。它们本来就在手机存储上，卸载 App 不会删。装好定制版后重新指定一次书目录即可。

### 备选做法

如果原版里书不多、设置也不复杂，直接在定制版里重新配置也行。

## 六、桌面歌词使用说明

### 开启

1. 打开一本书 → 中间点击调出菜单 → **Speech（朗读）** 启动朗读
2. 菜单里进 **Settings（设置）** → 打开 **Desktop lyrics（桌面歌词）** 开关
3. 点 **Lyrics appearance（歌词外观）** 调字号、颜色、透明度
4. 按 **HOME 键回到桌面** —— 悬浮歌词就出现了

### 显示规则

- **只在 App 退到后台时显示**，回到阅读界面会自动隐藏（避免和 App 内浮条重复）
- 三段式：上一句 / 当前句（更大更粗） / 下一句，**全靠字号区分，不靠变淡**
- **文字永远清晰**：所有文字都是**完全不透明**的纯色。设置里的「背景透明度」**只作用于悬浮窗背景**，
  无论背景调多透，文字都不会跟着变淡。
- **逐字推进**：当前句里 **已读的字 = 已读进度颜色，未读的字 = 歌词颜色**。
  两者默认都是白色，所以默认观感是**一整句均匀清晰的白字**；
  想看到逐字点亮的进度，把「已读进度颜色」另选一个颜色即可（如淡金色）。
- **熄屏 / 锁屏**：熄屏后歌词窗自动隐藏且停止刷新；锁屏时被系统盖住看不见；亮屏解锁后自动恢复（见第七节）
- **暂停即收起**：只要朗读处于暂停状态（双击歌词、点 ⏯、耳机暂停、来电打断…），歌词窗就自动收起；
  **重新开始播放的那一刻它自己回来**，不用手动再开。想边暂停边看最后一句的场景，请用 App 内的朗读浮条。

### 操作

| 操作 | 效果 |
|---|---|
| 拖动 | 上下移动位置，自动记忆 |
| **双击歌词** | **暂停朗读；窗口随即收起。恢复播放后自动重新出现** |
| 点 ⏮ | 上一句 |
| 点 ⏯ | 暂停 / 继续 |
| 点 ⏭ | 下一句 |
| 点 ✕ | 关闭歌词（同时关掉开关） |
| **长按歌词** | 隐藏 / 显示控制按钮（纯文字模式） |

### 可调项

| 项目 | 范围 | 默认 |
|---|---|---|
| 字号 | 12–36 sp | 20 |
| 歌词颜色 | 取色器 | 白色 |
| 已读进度颜色 | 取色器 | **与歌词颜色相同**（默认看不到逐字变化；改色即彩色扫读） |
| 背景透明度 | 0–100 | 45 | **只影响窗口背景**，文字始终不透明 |
| 显示前后句 | 开 / 关 | 开 |
| 显示控制按钮 | 开 / 关 | 开 |
| 只在后台显示 | 开 / 关 | 开 |
| 重置位置 | — | 一键恢复默认高度 |

## 七、常见问题

**Q：歌词不出来？**
检查两处：① 设置里 Desktop lyrics 开关是开的；② 系统设置里给了"显示在其他应用上层"权限。另外它**只在 App 退到后台时**才显示。

**Q：为什么有些字颜色不一样 / 变得发蓝？**
那是**逐字推进**效果——已读的字用「已读进度颜色」，未读的字用「歌词颜色」。
两者默认都是白色，所以默认看不到任何颜色差异；只有你自己把「已读进度颜色」改成了别的颜色才会显色。
2026-10-08 的 r2 已把默认调成同色，装 r2 之后不会再出现突兀的换色。

**Q：为什么文字看起来发灰、看不清？**
那是 r3 及更早版本的问题：未读文字用了 60% 透明度、上下句用了 55% 透明度，
悬浮在浅色壁纸上时会"糊"成灰色。**r4 已修复**——文字一律完全不透明，
「背景透明度」只作用于窗口背景。

**Q：锁屏 / 熄屏的时候歌词是不是自己关了？会费电吗？**
- **熄屏**：歌词窗会自动隐藏，同时**停止一切刷新与定时轮询** —— 完全不渲染，基本不产生额外耗电。
- **锁屏**：系统会把手动悬浮窗盖住，所以锁屏上看不到（这是 Android 的限制，第三方悬浮窗不能显示在锁屏上）。
- **不是"关闭"**：亮屏解锁回到桌面后会自动重新出现。
- **耗电主要来自朗读本身**（TTS 音频播放），跟歌词窗没关系。实测熄屏后朗读可正常连续推进。
- 如果希望**熄屏后长时间连续朗读**，可在朗读设置里打开「朗读时保持唤醒」（默认关）；打开后耗电会明显增加，按需使用。

**Q：逐字高亮的精细度不一样？**
取决于 TTS 引擎是否回调字级进度。部分引擎不回调，此时整句一起亮，不影响功能。

**Q：想回到原始状态怎么办？**
直接卸载「阅读·歌词版」即可。原版和它的数据**从头到尾没被碰过**。

**Q：两边同时用会不会冲突？**
不会。包名、数据目录、缓存全部独立。

## 十一、r3 更新记录（2026-10-08）

**安装包：`dist/Legado-3.26100809-r3-朗读桌面歌词-共存版.apk`**
（包名 / 签名与上一版完全一致，`versionCode` 38200 → 38201，**直接覆盖安装即可**，数据仍在）

### 改了什么

| 项 | 说明 |
|---|---|
| **双击悬浮窗 = 暂停 / 恢复** | 手势与"拖动""长按"并存：位移超阈值 → 拖动；按住 ≥550ms → 长按切按钮；两次点击（≤系统双击间隔、位置相近）→ 播放/暂停 |
| **暂停即隐藏悬浮窗** | 暂停态一律不显示（双击、点 ⏯、通知栏、耳机线控、来电打断…都算），恢复播放立即重新出现 |
| 暂停轻提示 | 双击暂停时弹一条 Toast「已暂停朗读，歌词暂时收起」，避免"点了两下窗口没了"的困惑 |
| 设置文案补充 | 「桌面歌词」开关的副标题写明三个手势与暂停行为 |

### 交互后果（重要，别当成 bug）

双击暂停后**悬浮窗会收起**，此时自然也就**没法再双击它来恢复**。恢复入口有三个，任选其一：

1. 通知栏 / 锁屏播放器的 **▶ 播放** 按钮
2. 耳机线控 / 蓝牙耳机上的播放键
3. 回到 App 的阅读界面点朗读浮条的 ⏯

一旦恢复播放，悬浮歌词**自动**回到原来的位置，无需任何额外操作。

> 如果更想要"暂停时也留着歌词、只是变暗"，告诉我，改一行判断即可。

| 恢复播放 | 窗口自动回来且继续推进 | ✅ 窗口数 0 → 1，句子由"娘子，护驾！"推进到"这里武道长青，百家争鸣。" |

### 实现摘要（便于日后维护）

- `ReadAloudLyricsWindow`：新增 `paused` 状态（用 `@Volatile`，因为音频焦点/来电等回调不在主线程），
  并入 `canShow()` 的门槛链：`开关 → 权限 → 未暂停 → 亮屏 → 在后台`。
- `updatePlayState()` 改为"改状态 + 收敛可见性"，并对非主线程调用自动切回主线程；
  播放/暂停图标与窗口显隐共用同一条路径，所以**任何**触发暂停的入口都会让窗口收起。
- `handleTouch()` 增加双击判定：`ViewConfiguration.getDoubleTapTimeout()` 内的两次抬手，
  且两次落点相差 ≤80px、期间无拖动、未触发长按，才算双击；长按触发后抬手不再计入双击。
- `BaseReadAloudService.newReadAloud()`：先 `updatePlayState(play)` 再推句子，
  避免"本次不自动播放"时窗口闪一下再消失。

（包名 / 签名与上一版完全一致，`versionCode` 38201 → 38202，**直接覆盖安装即可**，数据仍在）

### 改了什么

| 项 | 说明 |
|---|---|
| **文字不再有透明度** | 撤销所有作用于**前景**的半透明渲染，文字/图标一律完全不透明 |
| 未读文字 | r3 及更早：未读部分用 60% 不透明度的歌词色 → 看起来是灰字；现在**用歌词色原色，零透明** |
| 上下句 | r3 及更早：55% 不透明度 → 灰字；现在**原色零透明**，与当前句只靠**字号**区分 |
| 控制按钮图标 | 85% 不透明度 → 100% |
| **背景透明度语义收窄** | 该设置**只作用于悬浮窗背景**（圆角黑底），与文字无关。设置项下方新增说明文字 |
| 防呆 | 从配置读到的颜色一律强制 `alpha=0xFF`，即使历史配置里存了半透明色也不会生效 |

> 一句话：**透明度只属于窗户，不属于字。**

### 副作用（需要知道）

「已读进度颜色」与「歌词颜色」默认都是白色，所以**默认状态下看不到逐字推进的分界**，
当前句是一整句均匀的清晰白字（这正是这次要的效果）。
想重新看到"逐字点亮"的进度感，把 **已读进度颜色** 改成另一个颜色即可（例如淡金色 `#FFD54F`），
这样既保留进度可视，文字又始终不透明。

### 实测验证（Android 14 / arm64 模拟器，release 包 · 像素级）

在同一壁纸、同一悬浮位置下对比修复前后截图，统计悬浮窗内**中性色（灰阶）前景像素**：

|---|---|---|
| 纯白像素（灰度 ≥252） | 6659（占 19%） | 18068（占 52%） |
| **半透明灰像素（灰度 120–215）** | **14602** | **3181**（只剩字形抗锯齿边缘） |
| 150–162 区间灰像素（= 60% 白，即未读字） | 11510 | 232 |
| 133–145 区间灰像素（= 55% 白，即上下句） | 674 | 191 |
| 各行文字峰值灰度 | 255 / 156 | **255 / 255 / 255**（三行全为纯白） |
| 窗口背景合成色（灰度 ~100 桶） | 10143 | 9391（基本不变 → 背景透明度仍生效） |

### 实现摘要（便于日后维护）

- `ReadAloudLyricsWindow`：
  - 删除常量 `UNREAD_ALPHA`、`CONTEXT_ALPHA_RATIO` 与工具函数 `withAlpha()`
  - 新增 `opaque(color)`：强制 `alpha=0xFF`，所有前景取色统一走它
  - `applyCurrentSentence()`：未读区间改为 `ForegroundColorSpan(歌词原色)`，不再降透明
  - `applyTextAppearance()`：上下句与按钮图标直接使用不透明正文色
  - `createBackground()` 保持不变 —— 全项目**唯一**允许带 alpha 的地方
- 文案：`read_aloud_lyrics_text_color_summary` / `_highlight_color_summary` / `_show_context_summary` 改写，
  新增 `read_aloud_lyrics_bg_transparency_summary` 并挂到设置项

## 十三、r5 更新记录（2026-10-19）——网页端 OLED 纯黑主题 + 文字颜色

**安装包：`dist/Legado-3.26101921-r5-朗读歌词+OLED网页-共存版.apk`**
（包名 / 签名不变，`versionCode` 38202 → 38203，**直接覆盖安装即可**，数据仍在）

### 背景

电脑浏览器打开阅读的 web 服务时，原本只有一套「简陋黑暗模式」：

- 夜间背景是带纹理的深灰图，不是真黑 —— OLED 屏上灰底会显示成发光灰，费电又发灰；
- **正文颜色写死 `#666`**（深灰配灰底），白天在窗边基本看不清；
- 书架页书籍名写死 `#33373D`，黑底上几乎看不见；
- 工具按钮、设置项标签也都是 `#666`。

### 改了什么

| 项 | 说明 |
|---|---|
| **新增「OLED 纯黑」主题** | 设置 → 阅读主题的第 8 个色块（黑色圆点）。正文背景与页面背景都是 `#000000`，浮层 `#0A0A0A` 仅保留 1px 差异边 |
| **新增「文字颜色」选择** | 设置里新增一行：自动 / 纯白 / 米白 / 暖灰 / 浅灰 / 奶咖 / 淡青，点一下立刻生效并保存到服务端 |
| 正文默认色提亮 | 夜间自动色 `#666` → `#E8E2D6`（米白）；白天仍 `#262626` |
| 工具按钮 / 设置标签 | `#666` → `#D2D2D2` / `#B2B2B2`；纯黑主题下为 `#E6E6E6` / `#C4C4C4` |
| 书架页 | 侧栏与书墙纯黑，书名 `#F2F2F2`、作者 `#DCDCDC`、最近章节 `#ADADAD`；分隔改用 1px `#1C1C1C` |
| 目录弹窗 | 修掉「任何主题都当夜间」的判断错误，文字 `#EFEFEF` |
| 弹出面板 / 输入框 / 消息条 | 纯黑主题下 element-plus 变量整体压到 `#000`，文字提到 `#F2F2F2` |

### 怎么用

1. 电脑浏览器打开 `http://<手机IP>:1122`（端口以 App 内显示为准）；
2. 点右侧竖排图标的 **设置**（第 2 个）；
3. 阅读主题选 **最右边那个黑圆点**（第 8 个，悬停提示「OLED 纯黑」）；
4. 下面一行「文字颜色」按喜好挑一个，不想要自定义就点「自动」。

设置保存在手机端的服务配置里，**换浏览器 / 换电脑都跟着走**，不用重设。

### 已知限制

- 书源编辑器页面（`/source`）跟随**系统**明暗（`prefers-color-scheme`），不跟这里选的阅读主题 ——
  系统是深色时它本来就是深色；如需强制纯黑，下次再加。
- 「文字颜色」是全局的：在浅色主题下手动选浅色文字会看不清，属预期（提示里已说明建议配暗色主题）。

## 十四、r6 更新记录（2026-10-19）——应用内更新上线

**安装包：`dist/Legado-3.26101921-r6-朗读歌词+OLED网页+应用内更新-共存版.apk`**
（包名 / 签名不变，`versionCode` 38204，**直接覆盖安装即可**，数据仍在）

### 这一版最重要的事：以后能自己更新了

以前「关于 → 检查更新」查的是**上游官方仓库**，而我们的包名（`com.legado.app.custom`）和签名都不同，
点更新只会下载到官方 APK，装上去是另一个 App，数据也不在那边 —— 等于白点。

现在改成读**本项目自己仓库**里的更新清单：

| 环节 | 说明 |
|---|---|
| 数据源 | `https://raw.githubusercontent.com/byl669/legado-lyrics-overlay/master/updates.json` |
| 备用镜像 | jsDelivr → fastly（前一个不通自动换下一个） |
| 版本判断 | 只看 `versionCode` 整数，不比较版本字符串 |
| 弹窗 | 上游原有界面：Markdown 更新说明 + 文件大小/日期 + 「立即更新」 |
| 下载 | Release 直链，备用 `ghfast.top` / `gh-proxy.com` 代理 |
| 自动检查 | 默认开，每 24 小时一次（设置里可关） |

### 怎么用

- **手动**：我的 → 关于 → 检查更新
- **自动**：装好后 24 小时内会自己查一次；有新版直接弹窗
- 不想被某个版本打扰：弹窗右上角菜单 → 忽略此版本

### ⚠️ 一次性动作（必须做）

**r5 及更早的包无法自己更新到 r6**（那时还指向上游）。
请手动安装一次本版 r6；从 r6 起，后续版本都能在应用内一键更新。

### 排查方法

检查更新失败时会写应用内日志：**我的 → 关于 → 保存日志**，搜 `AppUpdateCustom` 即可看到
每个镜像的命中/失败原因。常见原因就两种：网络不通（换网络重试）、清单缓存未刷新（等几分钟）。

> 顺带说明：`raw.githubusercontent.com` 有 5 分钟 CDN 缓存，刚发布完立刻查可能还是旧版本，等几分钟即可。
