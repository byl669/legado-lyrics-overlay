## 一、你的第一个问题：应用内更新加上了吗？

**之前没有，现在有了 —— 而且原来的其实是坏的。**

原版「检查更新」查的是上游 `LegadoTeam/legado` 的 Release。我们的包名是 `com.legado.app.custom`、
签名也是自建的，所以：

- 一旦上游发新版，我们的 App 会提示更新 → 下载**官方 APK** → 装上去是**另一个 App**，数据不在里面；
- 现在上游最新是 `3.26101819`，我们的版本名比它大，所以之前一直只显示「已是最新」——**纯摆设**。

### 现在的机制

| 环节 | 做法 |
|---|---|
| 数据源 | 本仓库根目录 `updates.json`（versionCode / versionName / url / size / sha256 / notes / pubDate） |
| 镜像 | `raw.githubusercontent.com` → `cdn.jsdelivr.net` → `fastly.jsdelivr.net`，前一个不通自动换下一个 |
| 版本判断 | **只比 `versionCode` 整数**（不比较版本字符串，避免时间戳式命名误判） |
| 弹窗 | 沿用上游 UI：Markdown 更新说明 + 大小/日期 + 立即更新 + 忽略此版本 |
| 下载 | `releases/latest/download/Legado-lyrics-overlay-latest.apk`，备用 ghfast.top / gh-proxy.com |
| 自动检查 | 默认开，每 24h 一次（设置可关） |
| 诊断 | 命中/失败的每个镜像都写应用内日志，「关于 → 保存日志」可查 `AppUpdateCustom` |

代码分流：`AppUpdate.isCustomBuild`（签名既非官方也非 Beta → `appVariant == UNKNOWN`）走 `AppUpdateCustom`，
上游官方包行为完全不变。

### ⚠️ 一次性动作

**r5 及更早的包无法自己更新到 r6**（那时还指向上游）。请手动装一次 r6；从 r6 起后续都能应用内更新。

## 五、已知限制

- `raw.githubusercontent.com` 有 **5 分钟 CDN 缓存**且 query 参数不影响缓存键 → 刚发布完立刻查可能还是旧值，等几分钟。
- jsDelivr `@master` 缓存最长 12 小时，只作兜底（代码里 raw 排第一，不影响即时性）。
- 书源编辑器页（`/source`）仍跟随系统明暗，未跟阅读主题；要它也纯黑是一处改动。
- 「文字颜色」是全局的：在浅色主题下手动选浅色文字会看不清（属预期）。
